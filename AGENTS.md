# Agent traps — HyperQuantMedia.github.io

Read and obey `../../AGENTS.md` (workspace-level standing rules) before anything
else.

Every trap below has cost real time at least once. They are facts about this
machine, this site and this repository — not session state, which lives in
`WAYPOINT.md` and is gitignored.

Two kinds are mixed here on purpose. Some will bite a developer. Some will bite
an agent specifically, because an agent sweeps a codebase looking for defects
and several correct things here look exactly like defects. **The expensive
failure is not missing a bug — it is "fixing" something that was already
right.**

## Indexing and crawling — things that look broken and are not

**`noindex` on six pages is deliberate. Do not remove it.** `/404.html` sets it
through `Base.astro`'s `noindex` prop, and the five Astro-generated redirect
stubs — `/solutions/`, `/get-started/`, `/home/`, `/ecosystem/`, `/titles/` —
carry it because a meta-refresh stub must never compete with its own target in
an index. None of the six is in the sitemap. **No page in the sitemap has ever
carried `noindex`**, so a grep hit is one of these six by definition.

**A search engine reporting `noindex` is not evidence the page has it.** Bing
reported exactly that on 2026-08-30 from a July crawl, which predates the DNS
cutover — what it held was the previous Wix site at this domain. Verify against
the live URL (`curl` the page, or the engine's live-fetch tool) before changing
anything. The cached verdict and the current page are different questions.

**`public/robots.txt` has a named AI-crawler group, and robots.txt groups do NOT
merge.** A crawler matching that group reads it and ignores `User-agent: *`
entirely. Any `Disallow` added to `*` must be repeated in the AI group, or it
silently fails to apply to the sixteen crawlers most likely to be quoting the
site. The file's explanatory comments were stripped on purpose; decision 9 in
`Design/reopenable-decisions.md` is where the reasoning lives.

**`/llms.txt` is generated by `src/pages/llms.txt.ts`. Do not hand-write it, and
do not add it to the sitemap.** It reads `src/data`, so it cannot drift from the
pages. Its absence from the sitemap is intended.

**The sitemap ships no `lastmod`, deliberately.** The Actions checkout is
shallow, so every page would get the build date — a fabricated freshness signal
is worse than none. Decision 7 carries the trigger and the fix.

## The owner's dev server

**Never run `astro dev stop`, and never start a second server on port 4321.**
Verification runs that start and stop servers silently kill the owner's HMR
socket — it presents to him as "hot reload stopped working", with nothing
pointing at the cause. Hit the running server read-only, or use another port.
One orphaned server, untracked by Astro's registry and unkillable by `astro dev
stop`, had to be killed by PID.

## DNS

**Do not pass an explicit resolver to `nslookup`.** `nslookup -type=TXT
_dmarc.hyperquantmedia.com` works; appending `8.8.8.8` or `1.1.1.1` times out,
because queries to arbitrary external resolvers do not leave this machine — the
configured resolver answers normally. `Resolve-DnsName -Server …` fails
identically. DNS is not blocked, and DNS-over-HTTPS is not needed. Recorded
2026-08-30, after an agent concluded the opposite from a single failed call and
worked around a problem that did not exist.

## Shell

**Backticks in `git commit -m` are shell-substituted and silently drop words.**
Write the message to a file and use `git commit -F`. The commit still succeeds,
with words missing.

**`gh issue create --title` mangles a leading `/` under Git Bash.** MSYS path
conversion turned `/credits …` into `C:/Program Files/Git/credits …` in issue
#25's title. Prefix with `MSYS_NO_PATHCONV=1` and read the result back.

## curl against the live site

**`curl https://hyperquantmedia.com/compendium` without the trailing slash is a
162-byte redirect**, and GitHub Pages sometimes drops that connection with
`curl: (56) schannel: server closed abruptly`. It reads as a broken page and is
not one. Use `curl -sSL` and/or the trailing slash.
